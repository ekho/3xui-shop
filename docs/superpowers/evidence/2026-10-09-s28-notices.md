## Наблюдаемый сценарий

TestNativeNotices собирает настоящий cmd/server и запускает serve, завершает и запускает его ещё два раза. Только Telegram Bot API имитируется собственным HTTPS-сервером через строгий loopback CONNECT proxy. Минимальное окружение дочернего процесса не наследует реальные токены; тестовая CA применяется к этому процессу, без изменения доверия macOS.

- Preview ничего не отправляет. All-confirm фиксирует двух первоначальных адресатов; поздняя регистрация исключена. Кабинет, plain-text письмо через TLS SMTP и фактический Bot API sendMessage получают подготовленное содержание.
- Повтор подтверждения после перезапуска сохраняет идентификаторы, число jobs/писем/вызовов и снимок аккаунтов, trial/access/order/receipt/refund. Edit меняет записанный Telegram message ID, не отправляя новое письмо.
- Чужой callback не закрывает запись; собственный on1 вызывает настоящий deleteMessage у имитируемого провайдера. Withdraw очищает кабинет и сохраняет уже доставленное письмо и бизнес-факты.
- Провайдер сохраняет копию и теряет HTTP-ответ. После завершения этой попытки и перезапуска результат остаётся unknown: новая отправка и удаление по выдуманному ID отсутствуют; копия у провайдера остаётся, кабинет очищается.
- Изменённые binding/consent пропускаются без переадресации. Отозванная роль запрещает подтверждение; предыдущие успешные action facts сохраняются. Обёртка панели блокирует и считает любые записи данных; их число в сценарии уведомлений равно0.

Стенд cabinet-native: семь собственных контейнеров, опубликованные порты только127.0.0.1, отдельные PostgreSQL/Redis и TLS Mailpit, 3X-UI `3.7.0@sha256:3b3131f1876e6bf35063a9ec4dd1c594e4525180bfc2e1c477dcc8a3c9550ca1`. Backend/gateway пересобраны из текущих продуктовых исходников; Telegram в Docker-профиле отключён. local.py check выбирает семь TestNativeTrial/Notices cases и затем проверяет остановку/возобновление compiled Docker backend, реальные panel readback и SMTP/reminder после перезапуска.

## Разобранные отклонения

Первый compiled запуск попал в исходную admin-БД: pgx ConnString сохраняет прежний URL после изменения ConnConfig.Database. Исправлен только путь к фактической изолированной тестовой БД. Исходный startup raw log был перезаписан; сохранённая диагностика явно частичная, полный Go failure log сохранён. Недостающие deleteMessage и актуальная message date добавлены в существующий nativeBot.

Полный web обнаружил семь ошибок старых cabinet fixtures без ответа нового inbox. Четыре существующих helpers получили пустой валидный список; device helper также получил пустой ответ прежних reminders. Проверки ошибок продукта сохранены. Первый Python-запуск не получил TEST_DATABASE_URL_FILE; исправлена среда команды, а не тест.

Первый полный native Docker-прогон остановил процесс по unknown, который записывается ещё до сетевой отправки. Исправлен тест: дождаться фактической копии и terminal legacy delivery после потерянного ответа. Продуктовый код и все прочие тестовые байты полному Go-прогону соответствуют; текущая полная native selection и vet проверили изменённый тест. Неизменившиеся1436 cases не повторялись локально; CI должен проверить весь точный source заново.

## Ограничения и доставка

Production, реальные деньги, live Telegram, внешний SMTP, Happ/VPN и macOS trust не использовались. Стенд доказывает локальный сценарий и поведение имитируемого провайдера; ограничения и политика настоящего Telegram не считаются внешне принятыми. С13 требует отдельного перевода пользователя и доступного провайдеру HTTPS callback.

Одно Astra/high whole-branch review и одна авторская Critical/Important correction pass ещё не проведены. CI, PR→v2, фактические merge parents/tree, annotated tag/prerelease и три OCI indices/шесть architecture labels ещё не подтверждены. Эти состояния обновляются отдельно от локальных тестов.
