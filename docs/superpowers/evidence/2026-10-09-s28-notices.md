## Наблюдаемый сценарий

TestNativeNotices собирает настоящий cmd/server, запускает serve и проверяет три перезапуска. Telegram Bot API имитируется собственным HTTPS-сервером через строгий loopback CONNECT proxy. Дочерний процесс не наследует реальные токены; тестовая CA применяется только к нему, без изменения доверия macOS.

- Preview ничего не отправляет. All-confirm фиксирует двух первоначальных адресатов; поздняя регистрация исключена. Кабинет, plain-text письмо через TLS SMTP и фактический sendMessage у имитируемого провайдера получают подготовленное содержание.
- Повтор подтверждения после перезапуска сохраняет идентификаторы, число jobs/писем/вызовов и снимок аккаунтов, trial/access/order/receipt/refund. Edit меняет записанный Telegram message ID без нового письма.
- Чужой callback не закрывает запись; собственный on1 вызывает deleteMessage у имитируемого провайдера. Withdraw очищает кабинет и сохраняет доставленное письмо и бизнес-факты.
- После потерянного send ACK результат остаётся unknown; отсутствуют новая отправка и удаление по выдуманному ID. Дополнительный сценарий удерживает ответ после записи копии провайдером, останавливает процесс до commit, восстанавливает lease и перезапускает backend: pending job завершается без второго send, unknown сохраняется.
- Изменённые binding/consent пропускаются без переадресации. Отозванная роль запрещает подтверждение; предыдущие успешные action facts сохраняются. Обёртка панели считает и блокирует записи; их число в уведомлениях равно0.

Стенд cabinet-native: семь собственных контейнеров, опубликованные порты только127.0.0.1, отдельные PostgreSQL/Redis и TLS Mailpit, 3X-UI `3.7.0@sha256:3b3131f1876e6bf35063a9ec4dd1c594e4525180bfc2e1c477dcc8a3c9550ca1`. Backend/gateway пересобраны из текущих продуктовых исходников; Telegram в Docker-профиле отключён. ID текущего backend image: `sha256:530d9f6a776e72a629f5abcf088041944a73e9cb6fe589cf5b6409d8ada28aff`.

local.py check выполняет12 верхнеуровневых TestNativeTrial/Notices сценариев (14 тестов и подтестов), включая оба браузерных. Затем проверяет остановку/возобновление compiled Docker backend, действительные panel readback и SMTP/reminder после перезапуска. JSON-проверка требует0 ошибок и0 пропущенных тестов; пакеты без тестов учитываются отдельно.

## Финальное ревью и один авторский проход

Один свежий gpt-6-astra/high whole-branch reviewer проверил пять Review Focus условий. Вердикт With fixes: Critical0, Important3, Minor0. Все три Important приняты и исправлены в одном авторском проходе:

1. Pending Telegram job после внешнего эффекта и прерванного commit могла повторно отправить сообщение. При fresh claim прежний unknown теперь приводит к завершению без сети, включая пятую попытку. Known429 сохраняет прежнюю повторную доставку. DB-тесты проверили первую и пятую попытки; compiled процесс подтвердил восстановление после реального завершения.
2. Незавершённый HTML-тег после видимого текста мог молча обрезать хвост. EOF теперь допускается только без оставшихся raw bytes; неполный открывающий/закрывающий тег и атрибут отклоняются.
3. Backend принимал XML-invalid BMP U+FFFE/U+FFFF и percent-encoded URL, которые браузер отвергал. Общие проверки Unicode и полного decoded URL согласованы на сервере и в web; реальный producer→consumer тест выполняется при RUN_BROWSER_TESTS=1.

Для каждого дефекта сохранён воспроизводимый RED и последующий GREEN. Первый запуск browser-helper обнаружил отсутствующий production define; это ошибка тестового окружения, а не semantic RED. После исправления были выполнены текущие focused и полные проверки. Второго ревью не было.

## Исправленные неточности приёмки

Предыдущее утверждение о семи native-сценариях отозвано: фактический selector выбирает12 верхнеуровневых сценариев. Старый local.py не задавал RUN_BROWSER_TESTS=1 и пропускал два браузерных сценария, что не было обнаружено по обычному Go-выводу. В полных Go-прогонах RUN_BROWSER_TESTS=1 был задан, браузерные сценарии прошли. CLI исправлен, вся его текущая selection повторена, отсутствие пропусков проверяется по JSON. Новые12/14 counts получены из фактических событий, не из списка предположений.

Ранние bootstrap/test-fixture отклонения (URL изолированной БД, неполный simulated Bot API, отсутствующие inbox ответы старых web fixtures, environment Python и слишком раннее ожидание unknown) сохранены в приватной хронологии. Их прежние результаты не выдаются за проверки текущих исправлений.

## Ограничения и доставка

Production, реальные деньги, live Telegram, внешний SMTP, Happ/VPN и macOS trust не использовались. Стенд доказывает локальный сценарий и поведение имитируемого провайдера; настоящий Telegram и внешний SMTP не считаются внешне принятыми. С13 требует отдельного перевода пользователя и доступного провайдеру HTTPS callback.

CI для точного source, PR→v2, фактические merge parents/tree, annotated tag/prerelease и три OCI indices/шесть architecture labels ещё не подтверждены. Эти состояния обновляются отдельно от локальных тестов. Issue38 остаётся OPEN до доставки.
