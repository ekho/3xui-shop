## Поведение

/start, /help, /support открывают Mini App. Startup проверяет webhook, getMe/token ID,
username/Main Mini App и ставит menu на текущий CABINET_ORIGIN. Неисправный Telegram
не останавливает HTTP/выдачу. Команды не создают аккаунт до подписанного согласия.

Старые navigation callbacks проверяют private actor, sender текущего бота и фактическую
кнопку. Payments разбирает nine-part данные: допускает незавершённые нули, отклоняет
чужой ID/flags/неизвестный state/overflow. Pay-button не подтверждает деньги. Только
single exact owned immutable invoice даёт source_id; нулевая цена/нет совпадения/
неоднозначность открывают полную legacy-историю. Фильтр всегда ограничен account_id,
чужой ID возвращает пустую страницу, cursor с фильтром запрещён.

notifications владеет additive migration00026 и отдельным UNIQUE(account,event) outbox.
Trial decision/outcome, paid-access outcome и operator text/file reply ставят generic
ru/en notice в той же Tx. Проверяются текущие binding/version/consent/source/ban/quarantine,
Telegram guard → account → job, same connection с MaxConns1, 60s DB-clock lease и 10s send.
Просроченный/короткий/поддельный lease и изменённые metadata не отправляются. Отозванный
получатель skipped. 403/400 terminal failed, lost/429 pending. Закрытие cn1 требует
доставленного message ID и текущего получателя. Downgrade при любом delivery fact запрещён.

  committed client notice, до T3 старые navigation/close не работали, HTTP filter
  отвергался400 и браузер не открывал адресную архивную запись.
- Credential version начинается с0; outbox/guard принимают0 без ослабления ограничений.
- Ошибочные consent/display_name fixtures нарушали существующий account_source;
  исправлены fixtures. Отсутствовавший test Tx rollback исправлен после остановки только
  проверенного собственного зависшего test child; ограничения БД сохранены.
- Первый platform test имел неверный exact label selector. На исходном Connection
  исправленный тест действительно получил ios вместо macos; затем GREEN для безопасного
  allowlisted выбора, без чтения VPN-ключа.
- Первый full Python запуск не унаследовал test-only URL-file env; nested Go отказал до
  доступа к данным. Исправлено окружение команды. Старый retry browser test имел два
  alert; проверяется именно ошибка отправки с прежними CSRF/idempotency assertions.
- Первоначальный Native helper был operator-only. Явный client mode передаёт текущий
  origin; исходный /start assertion RED15.62s, затем complete native GREEN10.726s.

- First full Go/race run exposed four existing operator/Telegram-trial checks using supported positive-int64 legacy identities. Central notification enqueue had rejected IDs beyond the real Telegram actor range and aborted domain transactions. TestClientTelegramLegacyRecipient reproduced INVALID_INPUT before the fix; enqueue now omits only unsupported recipients after complete metadata validation, preserving business facts and the old API.

## Rulings

1. recipient guard holds account/job transaction for bounded 10s send — prevents unlink/quarantine/restriction races using one connection without new infrastructure — cost if wrong: transient credential/restriction wait up to send timeout.

2. /start preserves source at signed Mini consent/login, not when unregistered user sends command — reuse accepted accounts first-source contract; no pre-consent account/source table — cost if wrong: source from a never-opened first link is not attributed.

3. old pay-button snapshot often has price=0 and no unique order ID — exact single owned invoice maps to source ID; otherwise full legacy history — cost if wrong: user may need select old transaction manually.

4. addressed immutable legacy fact uses optional legacy_source_id on existing history input — avoids unbounded page scans/new public endpoint — cost if wrong: one additive input field/front-end filter to maintain.

5. planned CompositionLifecycle regex misses actual TestNativeLifecycle names — use NativeLifecycle in acceptance command — cost if wrong: startup/shutdown regression may be missed.

6. keep first recipient proof on duplicate business event, ON CONFLICT DO NOTHING — credential changes must not block an idempotent business replay — cost if wrong: stale notice is skipped; cabinet remains current.

7. preserve EXTERNAL_BILLING_UNVERIFIED for Telegram-bound checkout — paid-outcome test binds Telegram only after already funded/applied purchase and replays same outcome — cost if wrong: external Telegram payment route stays closed until C35.

8. actual order screen is /mini-app/orders/<id>, unlike cabinet/support/history — route follows existing web router — cost if wrong: notification opens cabinet instead of order.

9. reuse existing accounts.LookupTelegram — already public in operators.go — no redundant account lookup API — cost if wrong: existing public owner semantics must remain compatible.

10. public Telegram input keeps64-byte limit, archive quote decoder keeps prior unrestricted historical nine-part reading — preserves large imported quantities without accepting oversized callbacks — cost if wrong: confusing two trust boundaries.

11. payments normalizes validated nonpayment extend/change flags into routing state — Telegram never reimplements nine-part flags — cost if wrong: unfinished old renewal/change screens may open a fresh catalogue.

12. existing instructions live inside cabinet Connection, not a new page — anchor and allowlisted platform parameter preserve old platform intent; no automatic key reveal — cost if wrong: inactive subscription has no connection section.

13. original Native fixture was deliberately operator-only (empty origin) — explicit optional full-client mode now passes current CabinetOrigin, keeping existing operator tests unchanged — cost if wrong: confusing test-only operator assembly with production. Native /start assertion actually RED15.62s before wiring, GREEN10.726s with real owned TLS3XUI3.7/SMTP and restarted whole graph.

14. fixture HTTP helper accepts optional in-memory Mini bearer and test-owned signing public key — exercises actual API/CSRF/signature/consent, no new production auth hook — cost if wrong: test signature could accidentally use wrong bot/clock.

15. old web-trial retry test had ambiguous alert selector (operation error plus stale-usage warning) — scope assertion to actual operation error and wait on second observed key — cost if wrong: copy change requires test update; idempotency/CSRF checks retained.

16. task-done invokes one full-Go check then commits only after its actual exit0 — records exact tested Native source range without repeating full Go solely for ledger — cost if wrong: commit failure prevents completion record; pending source remains reviewable.

17. existing operator/legacy identity contract accepts positive int64 while real Telegram actor/input accepts 52 bits — validate notice metadata, then centrally omit unsupported recipient in notifications enqueue — cost if wrong: such legacy identity has no Telegram notice; business transaction and cabinet facts remain intact.
