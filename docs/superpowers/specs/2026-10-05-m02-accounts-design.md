## Результат и граница

`accounts` обслуживает существующие регистрацию/подтверждение email, вход,
сессии, восстановление/смену пароля, смену email, роли операторов,
ограничения аккаунтов и импорт legacy approval. Клиентские контракты
С01/С02/С06/С48 сохраняются. Покупка, триалы, поддержка и панельные операции
сохраняют своих владельцев и вызывают операции `accounts`.

SQL регистрации, сессий, credentials, ролей и аккаунтов находится в
`internal/modules/accounts/internal/store`; миграции схемы остаются общими.
Модуль не импортирует platform, глобальный store, wire, httpapi или app.
Публичные DTO используют UUID, время, строки, числа и nullable pointers.
Хеш пароля, токены проверок и модели sqlc не экспортируются как снимок аккаунта.

`Snapshot` передаёт необходимые существующим операциям идентификаторы,
вид аккаунта, ограничения, признак наличия пароля и метаданные доступа.
Регистрация сохраняет генерацию account/vpn/sub/panel identifiers.
SQL хранения метаданных доступа остаётся у владельца строки аккаунта;
правила подписки, панели и месячного сброса продолжают жить в прежнем коде
до М04. Никакого нового бизнес-правила в эти setters не добавляется.

## Сохранность транзакций и доступа

Для существующих совместных операций `accounts` принимает переданный `pgx.Tx`
в узких операциях Lock, LockOperatorPair, создания Telegram identity и записи
метаданных. Это инфраструктурный контракт текущего PostgreSQL, а не передача
репозитория или SQL вызывающему модулю. Транзакцию завершает текущий сценарий.
Не вводятся вторая транзакция, общий event bus или универсальный Unit of Work.

Порядок блокировок сохраняется: аккаунты по UUID, затем роль; при изменении
credentials аккаунт перед сессией и email advisory locks. Отзыв роли,
ограничение, удаление сессий/доказательств и audit остаются атомарными.
Создание Telegram account, TrialGrant, Operation и job остаётся одной транзакцией.
Импорт legacy approval сохраняет dry run, конфликты идентичности и источника,
защиту операторов и отсутствие повторной записи при replay.

Сохранение idempotency для restriction использует прежние principal,
operation, JSON hash и результат. Уже записанный ключ после обновления
продолжает возвращать тот же ответ. Публичные коды/HTTP-статусы переводит bridge.

## Переходные зависимости

Один `accounts.Service` собирается в app и используется HTTP, CLI и jobs.
Старый `platform.NewService` остаётся совместимым конструктором для прежних
consumers/tests; это переходный фасад до М06, без второй реализации правил.
Bridge преобразует wire/legacy store DTO только за пределами модуля.

Письма проверки безопасности и их устойчивые задания переносятся вместе с
auth-кодом, поскольку worker проверяет срок и отзыв доказательства перед
отправкой. SMTP предоставляется callback текущего транспорта; конфигурация
SMTP и общий notifications переносится по М06. Job kind `mail_delivery`,
его JSON и max attempts=5 сохраняются. Существующая SMTP/advisory-lock
линеаризация с timeout=10 секунд сохраняется: перенос в М02 не меняет её
поведение; разделение доставки по М06 потребует отдельной проверки гонок.
Audit/idempotency записи конкретных auth-операций остаются в их транзакциях;
общий журнал и остальные операционные разделы переносятся по М06.

## Приёмка

1. Прямой путь accounts: регистрация, proof, login, исходный account ID;
   Snapshot не выдаёт пароль/хеш. Unicode и предел двух Argon2 работ сохранены.
2. Существующие проверки С01/С02/С06/С48 проходят через новый владелец,
   включая revoke-role concurrency, запрет ограничения оператора, proof races,
   restore, replay и dry run. Старые сессии/хеши/идентификаторы сохраняются.
3. CI проверяет импорты и отсутствие auth/role SQL вне владельца; генерация
   воспроизводима. HTTP/OpenAPI, go.mod/go.sum и история миграций не меняются.
4. Один native Go backend проходит текущую Docker-приёмку с 3X-UI **3.7.0**,
   TLS SMTP, Telegram outage/replay и физическим stop/start.
5. Свежий whole-branch review, исправления и PR в `v2`. Новое слияние и
   production отдельно; открытый PR #5/С10 не переписывается.

Реальный Telegram/payment provider, внешний SMTP/benchmark и живой Happ
не включаются в М02. Полное удаление Python остаётся С47.
