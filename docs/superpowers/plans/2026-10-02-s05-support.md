# С05: план поддержки

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Owned backend/frontend slices under enabled placement; coordinator owns contract/integration/commits. One fresh whole-branch review after С06.

**Goal:** Сохраняемая переписка с вложениями, состояниями и независимым support ban.
**Architecture:** Две PostgreSQL таблицы и общая роль operator_accounts; bytea attachment в транзакции сообщения. Polling/ack в web, тот же service для React-admin С06.
**Tech Stack:** Go/Echo/pgx/sqlc/Redis, React/TypeScript, Playwright; новые библиотеки не нужны.
**Spec:** [С05](../specs/2026-10-02-s05-support-design.md).

## Global Constraints

- Начать backend после release С03 migrations/store, frontend после release С04 web.
- One file10MiB, conversation50MiB, text4000 Unicode code points, filename128; one actor30/15min, request10MiB+16KiB.
- Page50, fixed sequence order; polling5s without overlap, explicit receipt only after render.
- Cookie actor/CSRF/Origin; checked role in write transaction; support_banned/restricted/vpn_banned независимы.
- Source contracts before consumers; private files downloadable/no inline or external preview; no legacy transcript invention.

## Review Focus

- RF1: file/payload mismatch with repeated key cannot create two messages or consume quota twice.
- RF2: role revoke and support ban racing a write cannot authorize by stale preflight.
- RF3: attachment owner authorization precedes bytes response and requires same message/conversation.
- RF4: failed recipient HTTP response does not mark message delivered.
- RF5: old history pagination does not lose concurrent new messages or undo sequence receipts.
