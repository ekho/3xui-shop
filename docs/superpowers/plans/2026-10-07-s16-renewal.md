# С16 — YooMoney renewal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Native, выбран владельцем) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Клиент продлевает текущий конечный тариф через YooMoney без Telegram,
с единственным начислением/сбросом и сохранением VPN-идентификаторов.

**Architecture:** Существующий funded purchase/access workflow получает
неизменяемое action=renew. subscriptions владеет правилами текущего тарифа,
vpn — чтением его provenance/записью панели, payments — деньгами и Stars guard.
Форма Catalogue и экран заказа переиспользуются.

**Tech Stack:** Go/Echo/pgx/River/sqlc/oapi-codegen, PostgreSQL/Redis,
React/TypeScript/Playwright, Docker, native 3X-UI3.7.0; новых зависимостей нет.

**Spec:** [2026-10-07-s16-renewal-design.md](../specs/2026-10-07-s16-renewal-design.md)

## Global Constraints

- `2026-10-07-s16-renewal-v1`, owner #23; архитектура `2026-10-05-modular-monolith-v1`.
- Все новые ветки — от origin/v2, без codex/, PR только в v2.
- Только YooMoney AC/PC для renew; первые покупки С10–С15 и старые hashes/proofs/IDs/job kind неизменны.
- Трафик сбрасывается один раз, срок max(native expiry, now)+days; UUID/sub_id/panel_key/server/ban сохраняются.
- Telegram/legacy billing unknown закрывается payments; полный Stars-переход в С35.
- SQL и private-пакеты только у своего владельца; network I/O вне SQL transaction.
- Только отдельный localhost Docker/native3X-UI3.7.0 и синтетические деньги/данные.
- Live Happ/VPN, production, реальный кошелёк, публичный callback, внешние SMTP/Telegram и доверие Mac не входят.
- Один fresh final reviewer после всех tasks; SHA-guarded manual merge и фактический v2 preview отдельно от локальной приёмки.

1. Изменение назначения/ban/Telegram identity между quote и физической записью сохраняет деньги и отказывает выдаче; Task1 поздние gates.

4. Lost response/смена локали сохраняют key/body, а fresh GET прекращает checkout при запрете; Task2 rendered tests.
5. Рестарт после funded target и restore сохраняют один срок/reset/actions/proofs/ID; Task3 native/read-only digest.
