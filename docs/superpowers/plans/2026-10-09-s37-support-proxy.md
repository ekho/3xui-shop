# С37 Telegram support-прокси Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execution is Native: coordinator implements each task, then ONE fresh whole-branch `gpt-6-astra/high` reviewer and ONE Critical/Important author correction pass, without a second review.

**Goal:** Сохранить Telegram support topics/text/media/commands и общий зарегистрированный web-диалог внутри одного Go-процесса.

**Architecture:** `support` owns mappings/receipts/jobs/guest ban/import; `telegram.Runtime` переиспользуется вторым экземпляром с отдельным token. Accounts повторно проверяет private source context под caller-Tx locks, subscriptions выполняет comp/reset/current trial, audit_reports сохраняет actual/unknown source. App только собирает owners; новые зависимости не нужны.

**Tech Stack:** Go stdlib, существующие pgx/sqlc/goose/River/Redis, Echo/OpenAPI, React/React-admin/Playwright, PostgreSQL и локальный Docker.

**Spec:** [2026-10-09-s37-support-proxy-design.md](../specs/2026-10-09-s37-support-proxy-design.md), версия `2026-10-09-s37-support-proxy-v1`, owner [#40](https://github.com/ekho/3xui-shop/issues/40).

## Review Focus

1. Provider update ID стал меньше после недели простоя или обновился display name: logical message replay не теряет сообщение и не дублирует его — Task 1 source tests.
2. Роль/привязка изменилась между первой panel-read и второй domain Tx: никакой compensation/reset от старого actor — Task 2 multi-phase source race.
3. Guest зарегистрировался или raw TG оказался у другого account: guest ban сохраняется, старые bodies/topic не передаются — Task 2 identity/import tests.
4. Long text+file: первый wire подтверждён, второй ACK потерян; confirmed retry повторяет только второй — Task 2 delivery parts test.
5. Оператор переключил client во время ответа history/retry: прежний dialog/file/form/result не остаётся на экране — Task 3 rendered scope test.
