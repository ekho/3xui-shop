# М02: accounts — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans; the owner selected Native. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Перенести существующие аккаунты, credentials, сессии, роли и ограничения
в accounts без изменения клиентского поведения и сохранённых идентификаторов.

**Architecture:** Модуль владеет приватным SQL и neutral DTO; переходный фасад
переводит прежние wire/store данные. Узкие транзакционные операции сохраняют
существующие locks и атомарность, SMTP остаётся переданным callback.

**Tech Stack:** Существующие Go, pgx/sqlc, River, Redis, testing; без новых зависимостей.

**Spec:** [М02](../specs/2026-10-05-m02-accounts-design.md),
[модульный монолит](../specs/2026-10-05-modular-monolith-design.md).

Baseline: `896a883c96bf662dc568372046fca75ae0753d33` (`origin/v2`).
Ветка `feature/m02-accounts`, PR в `v2`. Разрешение на автономное ведение
документов/реализации сохраняется; повторное одобрение не требуется.

## Global Constraints

- Один Go-процесс, один go.mod; текущие API, schema, secrets и identifiers сохранены.
- accounts не импортирует platform/store/wire/httpapi/app или чужую private реализацию.
- Snapshot не содержит password hash; DTO не содержат sqlc/pgtype/Echo типы.
- Account locks перед ролью/session; прежние idempotency hash и JSON сохраняются.
- Auth/password/proof ограничения и generic unknown-email ответы неизменны.
- Производственный конструктор в app; legacy facade содержит только conversions.
- 3X-UI **3.7.0**, собственные тестовые DB/SMTP, simulated Telegram; Happ не переключать.
- Conventional Commits и Co-Authored; не переписывать PR #5, не менять production.

## Review Focus

1. Отзыв роли во время защищённой операции: прежняя сериализация; Task 2/3.
2. Предсуществующая сессия или password hash: сохраняется вход и ограничение; Task 1/4.
3. Email proof/отзыв одновременно с доставкой: прежние gates и locks; Task 1/4.
4. Replay restriction после переноса: тот же результат, audit и actor; Task 2.
5. Скрытая зависимость SQL/DTO через legacy bridge: границы импортов и данных; Task 3/4.
