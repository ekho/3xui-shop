# Предварительные релизы 3xui-mole

Новый проект **3xui-mole** начинает собственную нумерацию с **0.1.0**;
репозиторий пока остаётся
[`ekho/3xui-shop`](https://github.com/ekho/3xui-shop). Workflow формирует адреса
образов из `github.repository` с суффиксами `-backend` и `-web`, поэтому текущие
пакеты ниже сохраняют прежнее имя. Если репозиторий будет переименован, новые
публикации будут использовать его новый slug; адреса уже выпущенных образов
нужно учитывать отдельно при обновлении установок.

Рабочие ветки текущего проекта создаются от актуальной `v2`, PR направляются в `v2`.
После каждого изменения `v2` workflow `3xui-mole preview release` собирает и публикует
два Docker-образа для `linux/amd64` и `linux/arm64`:

| Компонент | Пакет GHCR |
| --- | --- |
| Backend | `ghcr.io/ekho/3xui-shop-backend` |
| Кабинет | `ghcr.io/ekho/3xui-shop-web` |

Каждый образ получает теги `dev`, `0.1.0-dev.N` и `sha-<полный SHA коммита>`.
`N` — номер запуска CI (`github.run_number`), не номер версии продукта;
повторный запуск той же сборки сохраняет номер. Начало с `N = 1` не гарантируется.
После успешной публикации обоих образов создаются аннотированный git-тег
`0.1.0-dev.N` на исходном коммите и GitHub Release с признаком prerelease.
Описание содержит исходный коммит, адреса образов и изменения из GitHub.
Повторный запуск проверяет существующий тег и не перемещает его.
Запуски сериализованы штатной очередью GitHub Actions: до 100 ожидающих сборок
сохраняются при новых push; при заполненной очереди GitHub отменяет новые запуски.

PR проверяет сборку обоих образов без публикации пакетов или релиза.
Публичные параметры кабинета задаются при запуске контейнера:
`TERMS_VERSION`, `PRIVACY_VERSION`, `TERMS_URL`, `PRIVACY_URL`, `SUPPORT_URL`.
Версии и HTTPS-адреса документов обязательны; адрес поддержки допускает HTTPS
или `mailto:`. Одинаковый образ можно использовать в разных окружениях.

Контейнер кабинета записывает эти публичные параметры в `/run/web-public/config.json`;
для read-only контейнера этот каталог монтируется как tmpfs с доступом пользователя
контейнера. Caddy обслуживает точный путь `/config.json` из `/run/web-public`
с `Cache-Control: no-store`; остальные маршруты сохраняют прежние правила.
Рабочая конфигурация приведена в `deploy/acceptance/compose.acceptance.yml`
и `deploy/acceptance/Caddyfile`. При отсутствующих или некорректных параметрах
кабинет сообщает об ошибке конфигурации и блокирует регистрацию.

С47 удаляет старый Python image и его release workflow из ветки `v2`.
История релизов прежнего проекта остаётся в Git; старые версии, теги и релизы
не переименовываются, эту ветку нельзя использовать для их выпуска.
Предварительные выпуски 3xui-mole не получают Docker-тег `latest` и не заменяют
последний стабильный GitHub Release. Развёртывание сервисов выполняется отдельно.

Проверка workflow:

```sh
go run github.com/rhysd/actionlint/cmd/actionlint@v1.7.12 \
  -ignore 'unexpected key "queue" for "concurrency" section' \
  .github/workflows/preview-release.yml
```

Actionlint 1.7.12 ещё не распознаёт `concurrency.queue`, поэтому исключается только
эта диагностика. Значение `max` поддерживает GitHub Actions; серверная проверка
workflow и сборки выполняются на каждом PR в `v2`.
