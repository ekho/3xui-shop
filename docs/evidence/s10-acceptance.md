# С10: первая покупка через YooMoney

Реализован общий заказ первой покупки для подтверждённого web-аккаунта:
серверный снимок цены, POST-форма YooMoney, подписанное подтверждение денег
и отдельная очередь выдачи. Покупка нового доступа и переход с конечного
триала используют существующий AccessWorker. Оплата не зависит от Telegram.

## Проверенные границы

Backend проверен с настоящими изолированными PostgreSQL/Redis:
`RUN_BROWSER_TESTS=1 go test -race ./... -count=1` — PASS, все шесть пакетов
с тестами; `go vet ./...` — PASS. Браузерная регрессия — **126/126 PASS**,
Python — **105/105 PASS**. Каноническая генерация повторно дала идентичные
файлы, OpenAPI валиден, проверка semantic naming и `git diff --check` прошли.

| Условие | Факт проверки |
| --- | --- |
| Цена и доступ к заказу | Immutable quote, точные суммы выше 2^53, актуальная revision, чужой заказ, CSRF/Origin и права проверены HTTP/PG тестами. |
| Подлинность денег | Официальный HMAC-SHA256/RFC3986 вектор, изменённые поля, повтор поля, SHA1-only и тестовое уведомление проверены; gross/net учитываются отдельно. |
| Повтор и поздний перевод | Один receipt ID не удваивает выдачу; второй настоящий ID сохраняется отдельно. Отмена, поздний перевод и два разных заказа проверены конкурентными PG тестами. |
| Право на исполнение | Paid без подходящего funding receipt не даёт выдачу или операторский retry. Бан, смена аккаунта и спорный receipt проверяются до native write. |
| Срок и восстановление | Активный/истёкший триал, постоянные идентификаторы, абсолютный target, неоднозначный reset и восстановление существующей операции проверены source-тестами. |
| Клиент и оператор | Отмена/expiry позволяют новый неоплаченный заказ; paid/open/review сохраняют запрет. Отдельные payment/fulfillment состояния, lost response, reload, RU/EN, 375px и operator retry покрыты Playwright. |

## Реальный локальный стенд

На собственном HTTPS Docker-стенде с **3X-UI 3.7.0** перед migration15
закрыт ingress, остановлен backend и сохранён dump. До запуска новых workers
сверены прежние account identities, trial requests/operations/grants и
access operations: число аккаунтов и все сравниваемые digests совпали.

`LOCAL_STATE_DIR=<private-local-state> python3 deploy/purchase/local.py check`
дал PASS: два synthetic клиента зарегистрированы и подтверждены через TLS
Mailpit, создан серверный заказ; test/tampered уведомления не подтвердили
оплату. Корректный callback на localhost дал paid и applied в реальной
панели. Новый клиент не получил фиктивный trial grant; действующий триал
сохранил идентификаторы/grant и получил ровно 30 дней к прежнему expiry.
Повтор callback не изменил доступ. Клиент получил активную подписку и ключ.

`... python3 deploy/purchase/local.py restore` дал PASS: при остановленной
локальной панели paid-заказ остался незавершённым; backend остановлен,
dump восстановлен в отдельную собственную базу. Заказы, receipts и access
состояние совпали. Очистка авторизации идемпотентна и не меняет деньги.
Workers восстановленной базы не запускались. Исходный backend после
возвращения панели выдал один доступ.

Свежий whole-branch review нашёл два дефекта отображения/срока checkout и
неполное покрытие приёмки. После фактически выполненных RED→GREEN проверок
повторный обзор не оставил Critical/Important замечаний: обычный fulfillment
review снимается после восстановления, receipt disputes сохраняются;
таймер expiry и authenticated GET перед формой запрещают stale оплату.
Добавлены purchase-specific cancellation/callback race, второй receipt после
applied, истёкший триал и явное подтверждение неоднозначного reset.
Native браузер проверен поэтапно: регистрация/подтверждение и вход; выбор
тарифа, точный POST заказа и явно нажатая платёжная форма; затем тот же
сохранённый заказ после обновления стенда. YooMoney POST перехвачен и
остановлен до сети. Возврат и reload оставили pending; RU/EN, клавиатура,
375px и чужой/анонимный заказ проверены. После подписанного localhost
callback экран показал applied и сохранил его после reload; native лимиты
совпали, кабинет показал и скрыл HTTPS ключ.

Оставшийся сегмент дал девять PASS записей и одну FAIL на итоговом контроле
консоли; ошибка catch-handler проверочного скрипта скрыла исходный assertion.
Эта запись сохранена. Отдельный read-only postflight подтвердил на текущем
стенде ноль JS/console errors и внешних запросов на applied/key пути.
Преднамеренный чужой запрос дал только ожидаемый HTTP404 в консоли, без JS
ошибок. Ранние harness ошибки POST response-body после навигации, ожидания
рендера и English текста на bare RU URL сохранены в приватных артефактах;
их не выдаём за успешные полные прогоны.
Точные команды, source hashes, ожидаемые/полученные значения и приватные
артефакты хранятся в `.superpowers/acceptance/purchase` и
`.superpowers/sdd/2026-10-03-s10-first-purchase`; секреты, cookies, адреса
клиентов, подписи уведомлений и VPN-ключи в публичные доказательства не входят.

Первый native прогон остановился на конфликте занятого devices slot старого
тестового тарифа. Helper теперь выбирает свободный slot, создаёт новый тариф
через API и сохраняет его ID для следующих проверок; прежний тариф не менялся.

Настоящий денежный перевод YooMoney, production, URL уведомлений кошелька,
установленный Happ, VPN и доверие сертификатам macOS этим результатом не
проверялись и не менялись. С13 покрыт первым адаптером локально; внешняя
приёмка провайдера и перенос старых платежей остаются отдельными этапами.
